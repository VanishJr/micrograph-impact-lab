## 2026-11-07 · Question fixed, data connected, first method and baseline

**Request (developer):** fix the research question; connect the dataset with a fixed dev/holdout split;
put all ground-truth reading in a separate evaluator, with a test that forbids methods from touching it;
write the first real method (classical watershed) test-first; show the reviewer overlay images;
run the literature step only once; add a one-time holdout exam (`run.py --final`).
No commit, no live run. Time box: first live run by 14:30.

**Question:** Can an agent loop tune a classical grain segmentation pipeline so that grain count and mean grain size on optical micrographs match ground truth within 10%,
and how does accuracy degrade with image noise?

**Data checks** (script against the files, all 36 synthetic images with complete rows):
- There is one `labels_grain` image per name, shared by `clean/` and `corrupted/`.
  The CSV rows describe that ground truth.
  `corruption_level` and `artifact_area_fraction` describe the corrupted version.
- Labels tile the whole image (no boundary pixels), and `area_um2 = area_px × um_per_px²`.
- `n_grains` = rows in `ground_truth_grains.csv` for 36/36 images: it counts all grains, edge-touching ones included.
- `mean_eq_diameter_um` = mean `eq_diameter_um` of grains with `touches_edge == 0` for 36/36 images: interior grains only.
- The 12 `magset*` rows (1.0 and 2.0 µm/px) have empty mean columns and no rows in `ground_truth_grains.csv`.
- `corruption_level` takes the values 0.15, 0.35, 0.5, 0.55, 0.75 and 0.95 (the brief said up to 0.75).
- 316L masks hold only 0 and 1; there are 6–39 grains per image (median 19) on val and test.
  The images are a mix of `.png` and `.jpg`.

**Synthetic set (90_SYNTHETIC_exact_ground_truth): provenance unconfirmed,**
likely generated by an AI-written script on the day;
generator code not available, so the images are not redistributed.
Asked the scientist for the generator script (open question Q-1).
Answer: the set was generated with AI prompts and edited by hand; neither the prompts nor the code exist any more.
The dataset's SOURCES.md claims a `_generator_code` folder that does not exist.
Decision: the synthetic set is a tuning testbed, not scientific evidence;
the main claim is measured on the real 316L images (Warren et al. 2024, Zenodo 10.5281/zenodo.22039777, CC BY 4.0).

**Decisions:**
- **Split** (`data/splits.json`, seed 0):
  - synthetic: magset excluded; per family 4 dev / 2 holdout → 24 / 12;
  - 316L: `val` → dev (40), `test` → holdout (165), `train` unused.
- **Evaluator** (`src/evaluate.py`), like with like:
  - Count: all grains vs `n_grains`, or interior vs interior when the method drops edge grains.
  - Size: mean equivalent diameter of interior grains on both sides, px → µm with `um_per_px`.
  - 316L: grains are 4-connected components of mask = 1, sizes in px.
  - Main metric `max_rel_error` = max(median |count error|, median |size error|) over dev, target ≤ 0.10.
- **Method** `watershed`:
  - Pipeline: denoise → boundary map → distance-transform markers → watershed.
  - Boundary map: `threshold | sobel | tophat`.
    Tophat was added to the brief because some synthetic grains are as dark as the boundary lines, so a global threshold marks them as boundary.
  - Defaults were not tuned on the real data.
- **Tests** use a Voronoi micrograph built in code ([tests/voronoi.py](tests/voronoi.py)) instead of copying synthetic files of unknown licence.
  `data/sample/` holds two 316L train images with masks.
- **Overlays** are JPEG (quality 85, at most 1024 px wide), so a commit stays small.
  Label images are gitignored.
- **No `--dry-run --final` on the real data:** it would show holdout numbers before tuning.
  `--final` is tested on the Voronoi fixture only.

**Baseline** (watershed, default params, dev split, no API; numbers from the `execute.json` files):

| Dataset | Images | max_rel_error | median count error (bias) | median size error (bias) | File |
|---|---|---|---|---|---|
| synthetic | 24 | 0.333 | 0.333 (+0.333) | 0.166 (−0.166) | [results/baseline/synthetic/execute.json](results/baseline/synthetic/execute.json) |
| 316L | 40 | 12.9 | 12.9 (+12.9) | 0.678 (−0.691) | [results/baseline/316L/execute.json](results/baseline/316L/execute.json) |

Both datasets are over-segmented.
On synthetic, the error follows the family more than the noise:
- columnar_duplex and elongated_single have count errors of +1.4 to +2.8, that is 2.4–3.8× too many grains;
  the overlay [columnar_duplex_00.jpg](results/baseline/synthetic/outputs/overlays/columnar_duplex_00.jpg) shows elongated grains cut into vertical slices by the distance-transform markers.
- fine_equiaxed_single has count errors of +0.11 to +0.25.

The median count error per corruption level is:

| Level | 0.15 | 0.35 | 0.5 | 0.55 | 0.75 | 0.95 |
|---|---|---|---|---|---|---|
| Median count error | 1.62 | 0.31 | 0.27 | 0.30 | 0.36 | 0.44 |
| Images | 3 | 5 | 4 | 5 | 4 | 3 |

With 3–5 images per level, which families land in a level confounds the noise trend:
level 0.15 holds the columnar and elongated images.
This is not yet a measurement of degradation with noise.

On 316L, the synthetic-oriented defaults find about 14× too many grains (count bias +12.9):
the parameters do not transfer, which is what the loop is for.
